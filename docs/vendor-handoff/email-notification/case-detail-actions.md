# 案件詳情：下載通報完成檔案與再次寄送通知

更新日期：民國 115 年 10 月 15 日。

## 已完成的展示介面

「通報案件查詢 → 檢視 → 案件詳情」底部，在「關閉」旁新增：

- **下載通報完成檔案（PDF）**：瀏覽器產生實際可下載的 PDF，列出案件、通報者、作業單位、完整通報項目、地點、聯絡資料及附件名稱。
- **再次寄送通知**：展開確認區，顯示案件、可編輯的收件信箱及附件名稱。收件者預設帶入目前登入者個人資料中的電子郵件，可自行指定另一個地址；每次只寄至此一收件者，不副知勞檢機構。必填並檢查郵件格式，可取消或確認；確認後列出本次指定地址，明確顯示未寄出郵件。變更此欄位不修改個人資料或原通報紀錄。

既有展示案件於首次檢視建立快照；新增或編輯危險作業通報於送出時建立新版本。此快照保存在本次頁面記憶體，重新整理即回到預設展示資料。後續閱讀、備查或改派不會改寫同一版本的下載內容。PDF 缺少原通報信箱或時間時顯示未提供。重寄的預設信箱與個人資料頁共用登入角色的展示帳號資料，沒有個人信箱時留白並要求輸入。

取消的案件仍可下載展示資料，但停用「通報完成通知」重寄，並顯示原因。下載和重寄確認不改變案件狀態；勞檢檢視案件時，仍依既有流程更新閱讀狀態。

**展示 PDF 不是實際寄過的附件，也不是正式通報證明。** 為使靜態網站無須載入外部字型，PDF 使用瀏覽器中文字型產生影像頁面，可自動換行及分頁；此版本不提供文字搜尋或輔助閱讀器的文件結構。正式服務須提供可搜尋、可存取的原始 PDF。

## 正式平台必須完成

1. 案件成功保存後，固定當次送出版本、通報時間、完整資料及附件，產製通報完成 PDF，保存檔案識別碼、檔名與雜湊。通知郵件與詳情下載必須使用同一份保存檔案，不依目前畫面重新產製。原始附件缺失時，回報無法下載及聯絡方式，不能用目前案件內容冒充原附件。
2. 下載入口由後端檢查登入者與案件權限，再以 `application/pdf`、附件下載檔名及私人快取限制回傳原檔。不能把正式案件 PDF 放入 GitHub Pages 公開目錄。
3. 重寄入口須驗證登入、案件權限與 CSRF 防護。前端以目前登入者個人資料中的電子郵件預填收件欄位，允許修改。後端接收本次 `recipient`，驗證其為單一有效電子郵件地址，再以此地址作為 To；Cc 與 Bcc 均為空，不沿用原通知的勞檢副本。收件地址不可用作案件授權依據。由原通知紀錄取得主旨、範本版本及同版本附件；重寄內文須使用不含「本通知已副知管轄勞動檢查機構」等不符事實敘述的版本，同時保留原通知紀錄。
4. 本次重寄是再次通知，不建立新案件、不變更送出版本、不更新勞檢閱讀狀態。已取消案件拒絕重寄完成通知；需要取消通知時依取消事件另行辦理。
5. 點擊後停用重寄按鈕並顯示處理中；後端以冪等識別、速率限制及排程狀態避免連點或多視窗重複寄送。排程受理僅顯示「已排入寄送」，郵件服務確認寄出後才顯示寄送成功；失敗可重試並有明確原因。
6. 記錄操作者、時間（臺灣時間）、原通知識別碼、附件版本、本次實際收件人、空白副本、重寄內文、寄送結果與錯誤。重寄保留案件內容與同版本附件，並新增寄送紀錄供追蹤；不覆寫原通知收件人、個人資料或案件通報者信箱。

建議介面為 `GET /api/cases/{caseId}/completion-document` 與 `POST /api/cases/{caseId}/notifications/{notificationId}/resend`；重寄請求包含 `{ "recipient": "user@example.test" }`，服務端不接受副本設定。此為交付契約建議，展示網站未實作或呼叫這些 API。信件內容由[訊息範本連動規格](template-maintenance-integration.md)管理，並套用上述重寄專用的收件與內文規則。

## 驗收

- 事業單位、勞檢及管理者在有案件權限時可從詳情下載；無權限與其他案件識別碼不能取得檔案。
- 下載檔名、雜湊及內容與原郵件附件一致；編輯、備查、改派後仍可追溯原送出版本。
- 中文、完整長作業名稱、多地點、多頁附件清單不截斷；檔案能正常開啟。
- 重寄預設地址與目前登入者個人資料一致，可指定其他信箱；空白、無效格式及多個地址無法確認。確認採用本次填入的地址，不改動個人資料或原通報者信箱。
- 重寄的 Cc／Bcc 為空，勞檢機構不收到副本，內文也不宣稱已副知。首次通報自動通知的既有副知規則維持。
- 取消不寄信，確認只建立一次寄送工作；失敗恢復操作並可重試。
- 取消案件不重寄完成通知；重寄不改變待確認／已備查，也不建立重複案件。
- 展示網站不呼叫郵件服務、不顯示虛假的成功寄出訊息；兩個網站入口均提供相同操作。
