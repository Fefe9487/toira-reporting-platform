# 案件詳情：下載通報完成檔案與再次寄送通知

更新日期：民國 115 年 10 月 15 日。

## 已完成的展示介面

「通報案件查詢 → 檢視 → 案件詳情」底部，在「關閉」旁新增：

- **下載通報完成檔案（PDF）**：瀏覽器產生實際可下載的 PDF，列出案件、通報者、作業單位、完整通報項目、地點、聯絡資料及附件名稱。
- **再次寄送通知**：展開確認區，顯示案件、填報者信箱、管轄機構及附件名稱，可取消或確認。確認後明確顯示未寄出郵件。

既有展示案件於首次檢視建立快照；新增或編輯危險作業通報於送出時建立新版本。此快照保存在本次頁面記憶體，重新整理即回到預設展示資料。後續閱讀、備查或改派不會改寫同一版本的下載內容。缺少信箱或通報時間時顯示未提供，不代填其他公司的資料。

取消的案件仍可下載展示資料，但停用「通報完成通知」重寄，並顯示原因。下載和重寄確認不改變案件狀態；勞檢檢視案件時，仍依既有流程更新閱讀狀態。

**展示 PDF 不是實際寄過的附件，也不是正式通報證明。** 為使靜態網站無須載入外部字型，PDF 使用瀏覽器中文字型產生影像頁面，可自動換行及分頁；此版本不提供文字搜尋或輔助閱讀器的文件結構。正式服務須提供可搜尋、可存取的原始 PDF。

## 正式平台必須完成

1. 案件成功保存後，固定當次送出版本、通報時間、完整資料及附件，產製通報完成 PDF，保存檔案識別碼、檔名與雜湊。通知郵件與詳情下載必須使用同一份保存檔案，不依目前畫面重新產製。原始附件缺失時，回報無法下載及聯絡方式，不能用目前案件內容冒充原附件。
2. 下載入口由後端檢查登入者與案件權限，再以 `application/pdf`、附件下載檔名及私人快取限制回傳原檔。不能把正式案件 PDF 放入 GitHub Pages 公開目錄。
3. 重寄入口須驗證登入、案件權限與 CSRF 防護。由後端通知紀錄取得收件人、副本、原主旨／內文、範本版本及同版本附件，不能接受任意收件地址或使用瀏覽器資料作為授權依據。確認區顯示實際收件對象；資料缺失須停止並提示補正。
4. 本次重寄是再次通知，不建立新案件、不變更送出版本、不更新勞檢閱讀狀態。已取消案件拒絕重寄完成通知；需要取消通知時依取消事件另行辦理。
5. 點擊後停用重寄按鈕並顯示處理中；後端以冪等識別、速率限制及排程狀態避免連點或多視窗重複寄送。排程受理僅顯示「已排入寄送」，郵件服務確認寄出後才顯示寄送成功；失敗可重試並有明確原因。
6. 記錄操作者、時間（臺灣時間）、原通知識別碼、附件版本、實際收件人、寄送結果與錯誤。重寄保留原內容，並新增寄送紀錄供追蹤。

建議介面為 `GET /api/cases/{caseId}/completion-document` 與 `POST /api/cases/{caseId}/notifications/{notificationId}/resend`；此為交付契約建議，展示網站未實作或呼叫這些 API。實際信件內容沿用[訊息範本連動規格](template-maintenance-integration.md)。

## 驗收

- 事業單位、勞檢及管理者在有案件權限時可從詳情下載；無權限與其他案件識別碼不能取得檔案。
- 下載檔名、雜湊及內容與原郵件附件一致；編輯、備查、改派後仍可追溯原送出版本。
- 中文、完整長作業名稱、多地點、多頁附件清單不截斷；檔案能正常開啟。
- 重寄先顯示實際收件對象；取消不寄信，確認只建立一次寄送工作；失敗恢復操作並可重試。
- 取消案件不重寄完成通知；重寄不改變待確認／已備查，也不建立重複案件。
- 展示網站不呼叫郵件服務、不顯示虛假的成功寄出訊息；兩個網站入口均提供相同操作。
