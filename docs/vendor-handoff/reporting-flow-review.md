# 通報流程問題與後續驗收

本文件彙整 115 年 11 月 27 日至 28 日對 GitHub 展示庫的本機檢查與獨立審查。審查基準為 `main` 的 `084bb28`，包含 [PR #7](https://github.com/Fefe9487/toira-reporting-platform/pull/7) 的工程通報變更。確認的問題以展示原型為準。正式版的資料庫、收案及郵件流程須在開發商的測試環境驗收。

## 已確認的交付範圍

- 站名統一使用「危險作業風險評估及通報平台」。首頁、登入頁、平台主頁、常見問答和下載專區的頁籤與分享預覽沿用此站名。T-OiRA 是外部風險評估工具，於操作說明和工具入口使用其名稱。
- 正式版案件查詢已取消「合併掃描」與「整組標讀」，採案件篩選。展示庫仍保留舊入口，且查詢條件尚未套用。展示庫若作為交付驗收畫面，須同步移除舊入口並驗證篩選確實作用。舊有整組標讀的角色檢查問題隨該功能下架一併驗收。 [案件查詢](../../js/modules/case_search.js#L153-L171) · [搜尋按鈕與清單](../../js/modules/case_search.js#L408-L460)
- 勞檢承辦人須在案件詳情按「確認已讀」，案件才會改為已備查。開啟詳情可先檢視資料，狀態維持原值。補登、改期、取消及其他修正完成後，最新異動回到未備查，原備查紀錄及取消事實應保留。
- 勞檢每 12 小時新增案件彙整涵蓋一定規模以上工程開工與重大變更，以及危險作業通報。跨轄案件副知相關轄區，各地區就所轄部分自行判斷及處理。 [彙整交付規格](email-notification/inspection-digest.md)
- 展示版已改為按鈕確認已讀，並可驗證修正後重新備查。正式環境的收案、分機關備查及郵件排程仍須由開發商驗收。

## 展示庫已確認的問題

### 優先修正

1. **位置與管轄選項會產生錯誤的收案資料。** 工程通報選擇其他縣市後，行政區仍只有臺北市選項，管轄機關也未連動。工程定位與地圖按鈕會讀寫危險作業通報欄位，定位被拒絕時共用函式還會代入示範座標。另在危險作業通報中，縣市連動重建選單時會移除初始選單的「經濟部產業園區管理局」。驗收至少涵蓋非臺北市、園區、舊案回填、定位遭拒，以及地址與 GPS 的一致性。適用機構名單與管轄條件由業務方確認。 [工程所在地](../../js/modules/construction_report.js#L514-L561) · [工程定位按鈕](../../js/modules/construction_report.js#L611-L619) · [管轄選單](../../js/data/geo_data.js#L191-L199) · [定位處理](../../js/data/geo_data.js#L341-L374)
2. **更動作業條件後，T-OiRA 舊確認可能繼續有效。** 開啟既有案件後，第一次更改人數、地點、承攬商或作業項目，可能保留原本的「已檢視、修正結果」勾選。現有測試先手動建立比對基準，實際編輯流程缺少同一個步驟。驗收要從開啟舊案開始，修改後首次進入第三步，確認評估結果的檢視勾選已撤回。 [編輯回填](../../js/modules/dangerous_report.js#L1163-L1169) · [評估變更檢核](../../js/modules/risk_assessment.js#L187-L234) · [回歸測試](../../scripts/verify_report_flow.cjs#L127-L144)
3. **原通報快照與首次通報時間可能遺失。** 尚未建立快照的危險作業舊案若直接編輯，修改後內容會成為第 1 版，原版無法追溯，主檔通報時間也會被更新。工程案每次重新產製的 PDF 都標為第 1 版，補登後次序改變時檔名仍相同。工程確認頁顯示預定開始日，PDF 卻可能顯示「預期作業期間 ～ 未提供」，或混用舊迄日與新起日。驗收要核對首次收件時間、各版送出時間、資料與 PDF，同一版下載及重寄應可追溯到同一份檔案。舊案若無原始附件，須如實標記可取得的資料。 [危險作業送出](../../js/modules/dangerous_report.js#L663-L678) · [工程資料儲存](../../js/modules/construction_report.js#L363-L382) · [文件快照](../../js/modules/case_completion.js#L5-L32) · [文件欄位](../../js/modules/report_document.js#L19-L63)

### 其餘修正與測試缺口

4. **日期與跨轄資料可不完整送出。** 工程開工的預定開始日標為必填，清空仍可儲存。重大變更發生日可留白，該筆會被排除在計次外。危險作業的起迄日通過格式及先後檢查後，仍可保留過去的預填日期。勾選跨轄時也可未指定副知機關，位置只填無法解析的 GPS 文字仍可通過。補齊已明定的欄位驗證，其餘依下列業務規則定案後驗收。 [工程驗證](../../js/modules/construction_report.js#L140-L180) · [危險作業驗證](../../js/modules/dangerous_report.js#L5-L114) · [副知資料](../../js/modules/dangerous_report.js#L689-L699)
5. **基地文字會拆散同一工程，或混入不同工程。** 重大變更以基地地號或地址文字比對，目前只做字元正規化與去空白。「臺／台」、地址與地號互填，以及同基地多項工程都須納入測試。正式版應以業務核定的工程識別方式串聯原開工案及重大變更。 [重大變更計次](../../js/modules/construction_report.js#L22-L46)
6. **附件清單可能列出未上傳的檔案。** 新增危險作業表單預填一般附件檔名，一般附件也只有容量上限檢查。驗收時應確認新案附件清單從空白開始，已列出的檔案都能取得，空檔、支援格式、大小及重複附件的處理符合規格。Q37 已同步每 12 小時的彙整範圍，發布後需驗收網站文字與實際通知一致。 [預填附件](../../js/modules/dangerous_report.js#L990-L1004) · [一般附件](../../js/data/geo_data.js#L389-L414) · [Q37 來源](../../js/data/qa_content.json#L372-L377) · [通知規格](email-notification/inspection-digest.md#L5-L13)
7. **示範案的清單與詳情使用不同資料。** `SC-115-09005` 的工程業主、施工者在清單與詳情不一致，部分危險作業示範案也有同類問題。驗收時按同一案號核對清單、篩選結果、詳情及 PDF，並確認更新後同步。 [示範清單](../../js/modules/case_search.js#L9-L17) · [工程案詳情](../../js/modules/dangerous_report.js#L328-L361)

## 待業務方確認的規則

- **管轄及改派。** 確認多點位的主轄、副知對象如何登錄、管轄不明時由誰協調，以及主轄、副知機關與管理者各自能檢視、改派或取消哪些案件。確認園區及其他特殊管轄的選項來源。
- **開工、補登、改期與取消。** 確認哪些情況允許補登、何時必須另立新案、跨日如何計算，以及由誰取消、是否留存原因與是否通知已收案機關。首次收件、預定作業、實際變更及取消時間應可分別核對。
- **工程重大變更。** 確認發生日是否必填、同基地不同工程如何區分、同日如何排序，以及補登或取消後的重排是否只反映於目前清單。另定案 50% 的比較基準、計算方式、前值為零的處理，以及哪些數值或說明必填。
- **異動通知。** 確認彙整已寄出後的改派、取消與新版本是否另行提醒。作業即將開始的案件，須明定誰負責在下次彙整前查看。 [彙整交付規格](email-notification/inspection-digest.md)
- **風險評估重新確認。** 明定哪些欄位變更需重新評估或換檔，以及哪些只須重新確認。T-OiRA 使用說明的既有勾選紀錄與本次評估結果是否仍適用，應各有可核對的紀錄。

## 正式環境及合併前驗收

- [ ] **送出與重試。** 模擬連點、逾時、斷線重送及兩個分頁同時編輯。同次提交只產生一個正式案號，舊版編輯不得覆蓋較新版本或已取消案件。確認同一工地的不同工項、期間或通報單位仍可各自成立。
- [ ] **資料與附件保存。** 模擬附件上傳中斷、檔案保存失敗和郵件寄送失敗。受理結果、附件可取用狀態和寄信結果應可各自追蹤。核對首次送出的 PDF 與同版下載、重寄的檔案一致。
- [ ] **收案、備查、通知與權限。** 使用主轄、副知及無權限的測試帳號，驗證開啟詳情狀態維持、按「確認已讀」才備查、補登／改期／取消後重新未備查。跨轄案驗證各機關能自行處理。以危險作業、工程開工、工程重大變更各一件測試同批統計，另測批次截止點、跨日、停機補列、重試、改派與取消。編輯或重寄既有案不會被算成新增案。
- [ ] **案件篩選。** 按正式版定案的條件驗證單選、組合篩選、無結果、清除及排序。清單與件數須使用相同條件，且各角色只會搜尋到其有權查看的案件。展示庫若作交付驗收，確認已移除合併掃描及整組標讀入口。
- [ ] **兩個入口的完整流程。** 從 `login.html` 和 `dashboard.html` 各跑開工及重大變更的新增、回填、編輯、檢視與下載。涵蓋非臺北市、多承攬商、同基地補登、聯絡方式必填、日期缺漏及 PDF 跨版本一致性。核對兩個入口載入相同版本的共用 CSS 和 JS。
- [ ] **提交與發布。** 以新 PR 補正已發布版本。合併前執行 `node scripts/verify_report_flow.cjs`，更動 FAQ 時執行 `python scripts/render_qa.py --check`。在 PR 記錄實測結果及待確認項目。發布後核對網址、頁籤標題、分享預覽與交付範圍。
