# 危險作業風險評估及通報平台

危險作業通報平台的電腦版展示原型，使用 HTML、CSS 與 JavaScript。

- 展示網站：https://fefe9487.github.io/toira-reporting-platform/
- 常見問答：https://fefe9487.github.io/toira-reporting-platform/faq.html
- 下載專區：https://fefe9487.github.io/toira-reporting-platform/downloads.html

## 展示範圍

首頁通報說明、四步驟通報流程、風險評估資料上傳介面、T-OiRA 作業評估建議、Q1–Q47 常見問答，以及通報第二步的勞檢機構特殊申報入口。

特殊申報網站維護只列出保留的機構，可新增、編輯、移除及撤銷移除；首頁不列出勞檢機構。移除特殊申報連結不會移除通報案件所需的管轄機構資料。原型設定仍保存於目前瀏覽器；正式設定須由後端共用資料庫維護。

案件狀態「待確認」表示勞檢尚未開啟資料；「已備查」表示勞檢已閱讀資料。展示流程已移除「退回」狀態，勞檢開啟案件後會更新閱讀狀態。

本專案供介面與流程展示。登入、案件資料、附件及管理功能仍為模擬或瀏覽器內的展示資料；未接上正式身分驗證、檔案儲存及主管機關通報服務。請以測試資料操作。

## 本機預覽

流程修正（115 年 11 月 6 日）：單筆取消會同步案件清單與詳情、記錄取消時間並停用重寄；取消或不存在的案件不能再編輯儲存。編輯保存的歷次通知快照存於 `completionNoticeHistory`，不會遞迴夾帶歷史資料。新增案件編號使用完整毫秒值與頁面序號，送出時重新驗證作業項目與日期。人數、承攬關係、附加點位及現場條件變更，或更換 T-OiRA 評估檔案時，須重新確認評估結果；既有案件免重勾 T-OiRA 說明的規則保留。

案件與版本歷史仍只存在目前頁面，重新整理會回到示範資料。案件查詢條件尚未實際套用篩選；一定規模營造通報儲存、改派、機構收案及郵件服務仍未接入。未實作的營造通報、改派及密碼重設，已改為明確提示尚未保存、改派或寄信，不顯示虛假的完成訊息。已備查案件修改後目前仍沿用原閱讀狀態；新版本是否改回「待確認」須另定流程規則。

回歸檢查：`node scripts/verify_report_flow.cjs`（不需安裝套件或連線）。涵蓋取消、版本歷史、案件編號、承攬與多點位資料保留、評估失效條件、最終送出驗證及修改入口。

在專案目錄啟動靜態網頁伺服器，例如：

```sh
python -m http.server 18767
```

開啟 `http://localhost:18767/`。本專案沒有建置步驟。

## 主要檔案

- `index.html`：首頁入口，轉至 `login.html`。
- `login.html`：登入封面及平台畫面。
- `dashboard.html`：平台畫面獨立入口。
- `faq.html`：常見問答，引用條文全文預設收合。
- `downloads.html`：前台下載專區；首頁與 Q&A 統一連至此頁。
- `js/data/downloads.json`：已定稿的下載文件清單，依清單順序顯示。
- `js/data/portal_config.js`：T-OiRA 與地方通報入口的預設設定。
- `js/data/toira_work_catalog.js`：通報作業與 T-OiRA 評估項目對照。

第三步選擇 T-OiRA 後，先顯示適用範圍、使用限制及法律責任的四項檢核表，逐項勾選全部確認後才顯示評估項目、工具入口及結果上傳區；取消任一項即關閉入口，並保存各項確認狀態於本次案件展示資料。確認涵蓋適用範圍、僅為輔助工具、雇主責任及現場修正；適用範圍依使用者定稿文字，列明危險性工作場所申請／定期評估／製程修改，或一定規模以上之事業單位不適用。新增案件切換評估方式或作業條件變更時，須重新確認。編輯既有案件時不再顯示或要求重勾 T-OiRA 說明檢核表，沿用已保存的確認資料；未保存逐項檢核資料的舊案件亦免重勾，不補記未曾勾選的確認。編輯時切換評估方式或修改作業條件亦維持免重勾；評估結果檢視及本次作業防護措施仍須依原流程確認。勾選不代表平台已審認適用資格。

第三步依第二步勾選的通報作業，以明確的作業識別碼查出可參考的 T-OiRA 評估項目，一項通報作業可對應多項評估，同一評估項目會合併顯示。高處影視拍攝（`filming-edge`）對應三種情境：高度二公尺以上邊緣及開口無法設置防墜設施之影視拍攝作業（HH-005）、影視受控墜落拍攝作業（HH-017）、威亞吊飛作業（HH-016）。使用者依實際拍攝情境參考，列出三項不代表每案都必須完成三份評估。作業庫版本與映射修訂日期分別記錄；原始來源雜湊保留作為來源追溯。

Q&A 內容維護於 `js/data/qa_content.json`，法條全文維護於 `js/data/qa_law_articles.json`。編輯後執行 `python scripts/render_qa.py` 產生 `faq.html`，並以 `python scripts/render_qa.py --check` 檢查同步。頁面仍為靜態 HTML，停用 JavaScript 時也能逐題閱讀及展開法條；頁首與導覽外框直接維護於 `faq.html`。

115 年 10 月 15 日依提供的 47 題 QA 編修稿及注意事項逐題核對補齊，採用可供操作手冊使用的問答文字。QA 頁面不放置編修、提供稿或原型建置狀態等註記；施行日期保留於法規依據題目及法條全文。通報的所有附件（一般附件、自行評估資料及 T-OiRA 評估結果）依署內規定統一每檔 15 MB；正式後端仍須執行同一容量檢查。

## 下載文件維護

下載專區沿用靜態網站，無須登入。首頁不直接連到個別下載檔案，下載資訊集中維護於 `js/data/downloads.json`。

僅將已確認可公開的文件放入 `assets/documents/`，並在清單中新增下列資料（清單順序即顯示順序）：

```json
[
  {
    "title": "已定稿的文件名稱",
    "description": "文件用途說明",
    "updated": "115 年 10 月 13 日",
    "format": "PDF",
    "size": "256 KB",
    "file": "assets/documents/example.pdf"
  }
]
```

上例僅為格式說明，未發布示範文件。`file` 必須指向本站 `assets/documents/` 下的實際檔案；`title` 與 `file` 必填，其餘欄位可省略。名稱與說明以文字顯示，不解析為 HTML。

未定稿的「危險作業線上風險評估及通報注意事項1151008.docx」已撤下，包括首頁與 Q&A 的引用及下載連結，草稿保存在網站根目錄外。目前清單為空，顯示「目前尚無提供下載的文件」。下架文件時也應將檔案移出網站公開目錄，以停用直接下載網址。

## 資訊公司建置需求：通知郵件

第四步確認頁、使用者案件檢視及通知附件已改用同一份通報文件模型，欄位與順序一致。第四步以編號分區及對齊資料列呈現，各區可返回修改；通知區列出確切的隨信 PDF 檔名並可下載預覽。隨信只有一份通報資料 PDF，包含完整通報欄位與一般／風險評估附件清單；原始檔案留存平台，不另夾入郵件。送出後保存當次文件快照，檢視、下載及重寄均使用該版本。詳見[三處內容對齊規格](docs/vendor-handoff/email-notification/report-document-alignment.md)。

正式平台須納入「通報完成通知郵件」功能：寄給第四步確認的必填通知信箱，Cc／Bcc 為空，不逐案副知勞檢。勞檢端改由後端每 12 小時依管轄機構寄送一封新增案件彙整提醒；沒有新增案件時不寄信，跨日未通知案件須補列。該欄預設帳戶電子郵件，填報者可修改；後端須驗證並保存當次送出版本的收件地址。郵件主旨與內文須由既有「訊息範本維護」統一管理，寄信後端依範本代碼讀取及帶入案件資料。請資訊公司依[通知郵件交付文件](docs/vendor-handoff/email-notification/README.md)、[勞檢每 12 小時彙整提醒規格](docs/vendor-handoff/email-notification/inspection-digest.md)及[訊息範本連動規格](docs/vendor-handoff/email-notification/template-maintenance-integration.md)實作。此為 115 年 11 月 7 日更新的開發需求，展示原型尚未啟用寄信或排程。

交付文件包含郵件版型與格式規格。Q32 說明通知內容與手動重寄的收件方式；寄件信箱與部分細節仍待核定，主系統未接入實際寄信功能。QA 採手冊用途的功能敘述，建置狀態由本文件與交付規格記錄。

案件詳情的「關閉」旁提供「下載通報完成檔案（PDF）」與「再次寄送通知」。PDF 為本次頁面中的展示資料快照，包含完整通報項目與附件清單；重寄收件者預設為目前登入者個人資料中的電子郵件，可自行修改，只寄至指定地址且不副知勞檢。重寄提供確認流程並明確標示未實際寄信，修改收件者不會改動個人資料。取消案件保留下載並停用完成通知重寄。正式平台須下載原郵件的同一份附件並由後端重寄，詳見[案件詳情操作交付規格](docs/vendor-handoff/email-notification/case-detail-actions.md)。
